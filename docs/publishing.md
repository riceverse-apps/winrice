# Publishing

> None of this has been run for real yet: the repository is private and there is no release. Treat it as a checklist to follow on the first release and fix what it does not cover.

## 1. Before the first release

- [ ] Confirm the flows (install, turn on, try mode, themes, undo, restore) on a clean Windows 11 VM and fix every `UNVERIFIED` item in the manifests that the release depends on.
- [ ] Make the repository public and enable *Private vulnerability reporting* (Security tab).
- [ ] Upload the social preview image (Settings → General → Social preview; GitHub only offers it on public repositories): `branding/social-preview.png` for WinRice. The same for the sibling repositories once they are public.
- [ ] Enable GitHub Pages with source *GitHub Actions* (for the landing page in `site/`).
- [ ] Decide about code signing. Without a certificate Windows SmartScreen warns on the installer; say so in the release notes.

## 2. A release

1. Bump the version in `app/package.json`, `app/src-tauri/Cargo.toml` and `app/src-tauri/tauri.conf.json`.
2. Run `npm run validate` and commit the regenerated `catalog/index.json`.
3. Tag and push: `git tag v0.1.0 && git push origin v0.1.0`.
4. `.github/workflows/release.yml` builds the NSIS installer on `windows-latest`, creates the GitHub Release, uploads the installer and its `.sha256`, and attaches the generated winget manifests.

## 3. winget

The winget manifests are generated from the release:

```bash
node scripts/make-winget.mjs --version 0.1.0 \
  --url https://github.com/riceverse-apps/winrice/releases/download/v0.1.0/WinRice_0.1.0_x64-setup.exe \
  --sha256 <sha256 of the installer>
```

This writes `packaging/winget/out/manifests/r/RiceverseApps/WinRice/0.1.0/*.yaml`. Validate and submit them to [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs):

```bash
winget validate --manifest packaging/winget/out/manifests/r/RiceverseApps/WinRice/0.1.0
```

then open a pull request that adds that folder (or use `wingetcreate update RiceverseApps.WinRice --version 0.1.0 --urls <url> --submit` after the first version is accepted). The package id is `RiceverseApps.WinRice`. Review by the winget team is outside our control and the installer must pass their automated checks.

## 4. Landing page

`site/index.html` is a static bilingual page, deployed by `.github/workflows/pages.yml` on every push to `main` that touches `site/`. It makes no promise beyond what exists: update the status text when the first release is out.

## 5. The remote catalog

`catalog/index.json` (generated by `npm run validate`) lets the app download new tools and themes without an update. It lists every file with its SHA-256; the app refuses files that do not match. Always regenerate and commit it together with catalog changes (CI fails if it is stale).
